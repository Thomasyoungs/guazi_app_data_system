# 飞书多人任务队列与主管复核绑定

## 多人提交

每条目标车消息都会生成独立 task_id，并绑定业务群、发送人、源消息和确认卡消息。任务创建后进入 `WAITING_TARGET_CONFIRMATION`，不会启动瓜子 APP，也不会写入 `data/current_target_task.json`。

确认卡会提示用户回复本条消息输入“确认”。系统优先用回复关系绑定确认卡；没有回复关系时，只在同一发送人、同一业务群恰好只有一个待确认任务时允许确认。若存在多个待确认任务，系统会要求回复对应确认卡。

## 串行队列

确认后的任务进入 `QUEUED`，并触发一次安全调度 kick。后台循环已运行时只入队，不重复启动；后台循环未运行时可执行一次安全队首调度检查。同一时间只允许一个任务占用 APP 控制状态，其他任务继续等待。dispatcher 取队首任务准备运行时，才写入 `data/current_target_task.json`。

## 主管复核

任务需要人工复核时，业务群只收到“已同步到主管复核群”的业务提示。主管复核群收到包含 task_id、复核原因、参考依据和价格链的复核卡。

主管确认价必须由 `config/feishu_roles.yaml` 中配置的 supervisor_open_ids 回复。绑定优先级为：回复复核卡、文本包含 task_id、主管群中只有一个待复核任务。若存在多个待复核任务且没有明确绑定，系统会要求回复对应复核卡，或输入“FSxxxx 8.6万”。

默认配置为空列表，属于安全模式；未配置主管 open_id 时，系统不会接受飞书人工改价。

## 群身份初始化

`config/feishu_roles.yaml` 支持 `admin_open_ids` 和 `supervisor_open_ids`。只有 `admin_open_ids` 中的用户可以初始化群身份和绑定一线群/主管群；未配置 `admin_open_ids` 时，所有群初始化命令都会安全拒绝。

管理员把机器人拉进一线业务群后，在群内发送：

```text
设置本群为一线群
```

管理员把机器人拉进主管复核群后，在群内发送：

```text
设置本群为主管群
```

然后管理员回到一线群发送：

```text
生成主管群绑定码
```

机器人会回复一次性绑定码，例如：

```text
绑定码：BD-4826
请在主管复核群发送：
绑定一线群 BD-4826
```

管理员在主管复核群发送对应命令后，一线群就会绑定到该主管复核群。绑定关系写入 `data/feishu_group_bindings.json`。绑定码有效期为 10 分钟，且只能使用一次。为避免误改关系，已绑定的一线群不会被同一命令覆盖。

管理员可在任一群发送：

```text
查看本群设置
```

输出只展示群身份和脱敏标识，不展示完整 chat_id 或 open_id。

未设置为一线群的普通群不能提交目标车模板；机器人会提示管理员先发送“设置本群为一线群”。一线群未绑定主管群时仍可提交目标车并排队，若任务进入人工复核，机器人会提示管理员完成主管群绑定。
