# AGENTS.md

本项目用于制作和维护“瓜子二手车 APP 数据获取系统”。后续 Codex 或人工开发必须遵守以下约束。

## 不可变输入

- `C:\Users\lzc93\Desktop\定价` 下的原始资料、历史文档、需求文档、视频只允许读取。
- 禁止修改、删除、重命名、覆盖任何原始资料文件。
- 所有新增代码、配置、日志、测试结果和导出结果只能写入 `guazi_app_data_system` 目录内。

## 自动化边界

- 可以使用 adb、UIAutomator、Appium、OCR、截图分析进行页面识别和流程验证。
- 禁止破解、反编译、抓包绕过接口、绕过验证码、规避风控或突破 APP 安全机制。
- 只采集字段契约允许的数据，禁止采集城市、标签、金融方案、联系方式、卖家信息、图片数量、浏览数等无关数据。

## 页面状态机

- 所有 APP 页面操作必须由页面状态机驱动。
- 页面契约命中后才能执行本状态允许动作。
- 页面契约不命中时，不允许业务点击；应先调用本地知识库或规则库，无法解决则记录问题并标记人工介入。
- 没有明确返回规则的页面，禁止自行返回。
- 执行返回后必须校验是否回到预期上一层；校验失败时立即重启 APP，不继续试错。

## 关键业务规则

- APP 启动后如有左下角广告倒计时“跳过”，优先点击；否则等待自动进入首页。
- 首页识别依据包含底部导航：首页、选车、卖车、我的。
- S03 品牌选择页强识别依据必须包含顶部“选择品牌”。
- 三同车源页面出现“综合排序”后，必须点击“综合排序”，再选择“价格从低到高”。
- 三同车源定义为相同年款内相同配置、相同年份、相同颜色；有多少采多少。
- 三同车源少于 3 台仍输出计算结果，但必须提示样本不足、结论参考性下降。
- 飞书任务编号、参考车序号由系统生成或回填，不允许人工填入。

## 开发与测试

- 优先使用 Python 标准库，避免不必要的外部依赖。
- 所有关键动作必须写审计日志。
- 所有异常必须结构化记录，支持后续学习循环沉淀。
- 修改关键模块后必须运行本地测试；手机连接失败不阻塞本地工程交付，但必须记录失败原因。
- 每次新增字段、动作、状态或异常，都应同步更新配置、文档和测试。

## 定价文件夹规则源约束

1. 桌面“定价”文件夹中的最新规则文件，是本项目最高规则依据。
2. 用户每次更新规则时，会先更新“定价”文件夹中的最新文件。
3. Codex 进行规则同步、配置同步、脚本同步、测试同步时，必须优先读取“定价”文件夹中的最新文件。
4. Codex 不得仅根据聊天窗口中的片段、摘要、口头描述、历史输出、旧 baseline、旧文档内容直接修改业务逻辑。
5. 聊天中的内容只能作为定位线索，不能替代“定价”文件夹中的最新规则文件。
6. 除非用户明确说“就按我这段内容改”或“这段内容覆盖文件规则”，否则 Codex 必须回到定价文件夹最新文件核验后再执行。
7. 如果聊天内容与定价文件夹最新文件不一致，以定价文件夹最新文件为准。
8. 如果定价文件夹内没有对应规则，Codex 不得猜测补规则，应输出 RULE_SOURCE_MISSING_NEEDS_USER_CONFIRMATION。
9. 如果发现多个同类最新候选文件且版本冲突，Codex 必须停止并提示用户确认唯一最新版本，不得自行选择。
10. 规则同步完成前，飞书定价系统不得直接按未同步的聊天内容运行。
11. 规则文件更新后，必须先同步 config/scripts/tests。
12. 测试通过后，新规则只用于后续任务或明确重新排队任务。
13. 正在运行中的任务不得中途切换规则。
14. 每个飞书任务应记录当时使用的 rule_version / rule_manifest。

## 规则同步执行边界

每次涉及规则、流程、页面契约、打分、竞争力系数、定价逻辑、飞书回写或 runner 状态机修改，必须先识别最新规则文件、读取规则源、只读对比当前 config/scripts/tests、输出差异、实施最小补丁、运行对应单测，并在测试通过后更新 sync_status。
