# 模块优先级与暂缓功能清单 V1

文档版本：V1  
阶段：Phase 0 项目基础  
状态：已建立  
适用范围：人人车 AI 经营中台模块优先级、暂缓功能和推进顺序。

## 1. 优先级原则

模块优先级按以下原则确定：

1. 先数据底座，后业务流程。
2. 先内部经营，后外部触达。
3. 先人工确认，后有限自动化。
4. 先可追溯，再追求效率。
5. 先低风险模块，再高责任模块。

## 2. P0 模块：第一阶段 MVP 必做

| 优先级 | 模块 | 目标 | 依赖 | 阶段输出 |
|---|---|---|---|---|
| P0 | 本地数据库底座 | 建立车辆经营主数据基础 | 阶段0文档 | 数据模型、数据字典、迁移方案 |
| P0 | 查博士数据导入/映射 | 将检测数据沉淀为本地标准字段 | 样例数据盘点 | 原始记录表、映射规则、校验报告 |
| P0 | 飞书定价结果入库 | 保存既有定价结果 | 定价结果边界确认 | 定价结果记录、来源记录、状态记录 |
| P0 | 库存管理 | 查看车辆在库状态、库龄、价格和风险 | 数据底座 | 库存视图、库存状态、车辆详情 |
| P0 | 调价/斩仓预警 | 基于库存数据提示经营风险 | 库存管理 | 预警规则、预警记录、处理状态 |
| P0 | AI 督导日报 | 给运营督导输出每日问题和建议 | 库存与预警数据 | 日报草稿、问题清单、建议动作 |
| P0 | 老板经营日报 | 给老板输出经营概览和重点风险 | 本地经营数据 | 指标摘要、风险摘要、重点车辆 |

## 3. P1 模块：MVP 稳定后再做

| 优先级 | 模块 | 推进条件 | 暂定目标 |
|---|---|---|---|
| P1 | 线索 AI | 库存、日报、动作日志稳定 | 辅助线索分级和跟进建议 |
| P1 | 小程序交易辅助 | 交易对象和权限边界明确 | 展示车辆、收集意向、人工确认交易动作 |
| P1 | 平台同步准备层 | 上下架审批、回滚和日志机制明确 | 建立同步前检查和任务队列 |
| P1 | 经营复盘分析 | 调价、预警、成交等历史数据积累 | 分析调价效果和库存周转 |

## 4. P2 模块：后续扩展

| 优先级 | 模块 | 说明 |
|---|---|---|
| P2 | 外部平台自动同步 | 必须在审批、日志、回滚机制成熟后再评估 |
| P2 | 客户触达自动化 | 必须在客户授权、话术合规和人工兜底机制成熟后再评估 |
| P2 | 车商拍卖 | 属于交易渠道扩展，需要独立产品设计 |
| P2 | C2C 撮合 | 属于交易模式扩展，需要独立风控和规则 |
| P2 | 实时语音提醒 | 属于交互增强，不是底座能力 |

## 5. 第一阶段暂缓功能清单

以下功能第一阶段明确不做：

| 功能 | 暂缓原因 | 后续重新评估条件 |
|---|---|---|
| 自动私信客户 | 外部触达风险高，容易产生不当承诺 | 客户授权、话术审核、人工兜底和日志机制建立 |
| 自动签合同 | 涉及法律责任和交易确认 | 合同模板、签署授权、法务审核和风控机制建立 |
| 自动收定金 | 涉及资金、支付和退款责任 | 支付资质、财务对账、退款规则和权限机制建立 |
| 自动上下架 | 涉及外部平台状态变更 | 审批流、回滚机制、同步日志和异常处理成熟 |
| C2C 撮合 | 不是内部经营数据闭环 | 车辆、客户、交易对象和风控模型成熟 |
| 车商拍卖 | 需要独立拍卖机制和渠道规则 | 车商准入、竞价规则、成交责任明确 |
| 实时语音提醒 | 非核心数据能力 | 日报和预警稳定后再评估提醒形态 |
| AI 直接改价 | 违反人工确认原则 | 仅可考虑“人工一键确认后执行”，仍需留痕 |
| AI 承诺车况 | 涉及重大责任 | AI 只能引用已确认检测结论，不得作出承诺 |

## 6. 暂缓功能的纪律

1. 暂缓功能不得以“临时脚本”“隐藏入口”“测试按钮”等方式绕过上线。
2. 暂缓功能不得在第一阶段数据库中创建可执行动作字段，避免误用。
3. 文档、代码、测试和验收清单中必须明确标注暂缓功能不可用。
4. 若业务需要提前变更优先级，必须更新关键决策表和验收标准。

## 7. 模块依赖顺序

建议推进顺序：

1. 查博士样例数据盘点。
2. 本地核心对象和字段字典。
3. 本地数据库底座。
4. 查博士原始记录保存和字段映射。
5. 飞书定价结果入库边界确认。
6. 库存管理基础视图。
7. 调价和斩仓预警规则。
8. AI 督导日报。
9. 老板经营日报。

不得跳过 1 至 5 直接开发日报、预警或外部同步功能。

## 8. 优先级调整机制

优先级调整必须满足：

1. 有明确业务原因。
2. 不破坏核心原则。
3. 不绕过人工确认。
4. 不影响现有飞书定价系统边界。
5. 更新本文档和阶段0关键决策表。
6. 在实施前形成验收标准。
