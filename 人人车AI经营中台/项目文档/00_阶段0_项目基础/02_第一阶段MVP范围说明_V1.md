# 第一阶段 MVP 范围说明 V1

文档版本：V1  
阶段：Phase 0 项目基础  
状态：已建立  
适用范围：人人车 AI 经营中台第一阶段 MVP 范围约束。

## 1. MVP 定义

第一阶段 MVP 是“内部经营数据闭环”的最小可用版本。它的目标不是替代销售、检测、财务或平台运营人员，而是先把车辆经营的关键数据收进本地数据库，并围绕库存经营形成可复盘、可预警、可汇总的内部工作台。

第一阶段只解决三个问题：

1. 数据能不能进来。
2. 车辆经营状态能不能被看见。
3. 经营风险和日报能不能被 AI 辅助解释。

第一阶段不解决外部交易闭环、客户自动触达、平台自动同步和自动执行动作。

## 2. 第一阶段包含范围

| 模块 | 是否纳入 MVP | 核心目标 | 输出 |
|---|---|---|---|
| 本地数据库底座 | 是 | 建立本地经营主数据 | 初版表结构、数据字典、迁移记录 |
| 查博士数据导入/映射 | 是 | 把检测与车况数据转为本地标准字段 | 原始记录、映射记录、导入校验结果 |
| 飞书定价结果入库 | 是 | 将既有定价结果沉淀为可追溯记录 | 定价结果表、来源记录、结果状态 |
| 库存管理 | 是 | 管理在库车辆、成本、价格、库龄和状态 | 库存列表、车辆详情、库存状态 |
| 调价/斩仓预警 | 是 | 根据库龄、价格、成本和风险规则提示动作 | 预警记录、建议说明、人工确认状态 |
| AI 督导日报 | 是 | 面向运营督导输出每日问题和建议 | 督导日报草稿、问题清单、动作建议 |
| 老板经营日报 | 是 | 面向老板输出经营概览和重点风险 | 经营日报、核心指标、重点车辆 |

## 3. 第一阶段明确不做

| 功能 | MVP 是否排除 | 排除原因 |
|---|---|---|
| 自动私信客户 | 排除 | 涉及外部触达和客户承诺，必须等数据和人工确认机制稳定后再评估 |
| 自动签合同 | 排除 | 涉及法律协议和交易责任，不属于内部数据底座阶段 |
| 自动收定金 | 排除 | 涉及支付、财务、风控和客户授权 |
| 自动上下架 | 排除 | 涉及外部平台状态变更，必须有审批和回滚机制 |
| C2C 撮合 | 排除 | 属于交易模式扩展，不属于第一阶段内部经营闭环 |
| 车商拍卖 | 排除 | 属于交易渠道扩展，需要独立规则和风控 |
| 实时语音提醒 | 排除 | 属于提醒交互形态，不影响数据底座建设 |
| AI 直接改价或承诺车况 | 排除 | 违反“AI先建议，人工确认后执行”的核心原则 |

## 4. MVP 业务流

第一阶段建议采用如下业务流：

1. 查博士数据以文件或人工导入方式进入本地导入区。
2. 系统保存查博士原始数据，并执行字段映射。
3. 映射后的检测、车况、配置等数据进入本地车辆相关对象。
4. 飞书定价结果以受控方式入库，形成定价结果记录。
5. 车辆进入库存管理视图，形成在库状态、库龄、成本、当前价格和风险指标。
6. 调价和斩仓规则生成预警记录。
7. AI 读取已入库数据，生成督导日报和老板经营日报草稿。
8. 人工确认需要执行的动作，系统记录确认结果和后续执行状态。

## 5. MVP 数据边界

第一阶段只处理内部经营所需的数据：

1. 车辆基础信息。
2. 检测与车况信息。
3. 定价结果信息。
4. 库存状态信息。
5. 成本、报价、调价、库龄和斩仓相关信息。
6. 日报指标和 AI 建议信息。
7. 人工确认与动作留痕信息。

第一阶段不处理或不主动采集：

1. 客户私聊内容。
2. 合同签署数据。
3. 支付凭证和收款流水。
4. 外部平台上下架状态变更。
5. 实时语音提醒数据。
6. 未经授权的个人敏感信息。

## 6. MVP 成功标准

第一阶段 MVP 成功的标准不是功能多，而是数据可信、边界清晰、可复盘。

验收时至少满足：

1. 本地数据库可以表达车辆、检测、定价、库存、预警、日报和动作日志。
2. 查博士样例数据可以被保留原始记录并映射到本地标准字段。
3. 飞书定价结果可以被保存为不可由用户伪造核心结果的记录。
4. 库存车辆可以按状态、库龄、价格、成本和风险进行查看。
5. 调价和斩仓预警有明确触发原因、建议动作和人工确认状态。
6. AI 督导日报和老板经营日报只基于本地已入库数据生成。
7. 所有关键动作都有操作者、时间、对象、动作前状态、动作后状态和原因。

## 7. MVP 不成功信号

出现以下情况，说明 MVP 方向偏离：

1. 尚未完成数据底座，就开始做客户自动触达。
2. 尚未建立动作留痕，就允许 AI 自动执行关键动作。
3. 尚未完成查博士字段盘点，就直接写死导入脚本。
4. 尚未明确飞书定价结果边界，就允许用户提交计算结果字段。
5. 尚未有库存状态定义，就开始做交易撮合或拍卖。
6. 把外部平台流程复制到本地，而不是建立自己的经营数据模型。

## 8. 阶段退出条件

第一阶段可以进入下一阶段的条件：

1. MVP 范围内的对象和字段已通过样例数据验证。
2. 导入、映射、入库、预警、日报的链路能够在本地完成。
3. 关键动作留痕通过验收。
4. 人工确认机制通过验收。
5. 暂缓功能没有被隐性实现或绕道上线。
